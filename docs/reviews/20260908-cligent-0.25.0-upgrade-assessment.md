## 结论

**建议升级到 npm 正式包 0.25.0，但必须同批迁移 usage 消费逻辑，不能只改版本号。** 当前 Node 和 SDK/CLI 固定版本满足上游支持下限；未发现当前调用参数的新增硬阻断。主要工作量在统计协议及其回归测试，而非 agent 编排重写。

本次完成评估与隔离检查，未升级项目依赖、修改运行实现或调用真实模型。上游逐项源码/spec 证据见[上游核验记录](./20260908-cligent-0.25.0-upstream-notes.md)。本地 cligent checkout 仅用于阅读；正式安装仍使用 npm 包和 lockfile。

| 变化 | 对本项目的实际收益与限制 |
| --- | --- |
| 0.21 修复 Claude 重复 init | 直接覆盖仍记录为 Open 的 CLI-008：hook/status/retry 等 system 消息不再冒充 init，每 turn 保持一次握手。上游已修复；本项目需真实 fresh/resume smoke 后才能标为 Verified。 |
| 0.21 重做用量统计 | Claude 使用完整 per-model 用量，减少子 agent 漏计；Codex 提供本轮根 thread 差值并明确 partial；缓存读写、reasoning、模型记录和费用来源可保留。只有下游迁移后才能得到这些收益。 |
| 0.21–0.22 OpenCode 归属与终止修复 | 改善 prompt/SSE 顺序及会话内用量归属，避免漏订阅或把历史后台活动算成本轮。其中自定义 messageID 导致挂起是新 accounting 开发期间引入并在 0.21 发布前修复，不能当作已证实存在于 0.20 的问题或本次额外收益。 |
| 0.22–0.23 异常/取消/权限处理 | 改善 Gemini 启动错误、各 adapter 取消优先级和连续性、Kimi 子进程回收、OpenCode 权限请求相关状态的回收和有界响应。对长时间 headless 评测有价值。 |
| 0.25 SESSION_RESUME_REJECTED | OpenCode/Kimi 可以明确报告“选中的 session 在执行 prompt 前已被拒绝”。便于将来安全地重建会话；库不会自动重试，目前 runner 仅消费 message，需透传 error code 才能让编排层使用。 |
| 0.24 fastMode | Claude/Codex 的可选新能力，当前无需启用，也不应全 adapter 统一传 `false`。不属于本次修复必需项。 |

## 必须调整的范围

1. **迁移 usage 边界与汇总语义。** 从 `usage.tokens.totals.input.total/output.total` 获取已观测总数；tokens 缺失保持 unknown，真实 0 保持 0；独立保留 `coverage`、records/cache/reasoning、`cost.source`。总数已含缓存和 reasoning，禁止再次相加。partial 是可信的部分范围，不能变成完整总量，也不应直接扔掉已有观测值。
2. **不能只改 TypeScript runner。** [single-engine](/Users/kgm/Projects/merico/deep-swe/wip/agents/deep_swe_agent/runtime/src/single-engine.ts:60)、[direct-engine](/Users/kgm/Projects/merico/deep-swe/wip/agents/deep_swe_agent/runtime/src/direct-engine.ts:128)、[RoleUsage](/Users/kgm/Projects/merico/deep-swe/wip/agents/deep_swe_agent/runtime/src/collaboration-engine.ts:77)、[Pier context](/Users/kgm/Projects/merico/deep-swe/wip/agents/deep_swe_agent/pier_agent.py:604) 和[直接读原始事件的 ATIF](/Users/kgm/Projects/merico/deep-swe/wip/agents/deep_swe_agent/atif.py:124)都要对齐。内部可保留旧字段作为展示投影，但必须额外保留新协议信息；历史 0.20 产物应继续可读。
3. **更新 token_usage 成本脚本。** [脚本头部](/Users/kgm/Projects/merico/deep-swe/wip/scripts/token_usage.py:14)仍写着缺缓存细项、依数量级推测 OpenCode input 口径；[费用计算](/Users/kgm/Projects/merico/deep-swe/wip/scripts/token_usage.py:124)按 role 配置模型和单一缓存字段估算。新版有多模型 records/不同 coverage，不能一律按主模型或把未报告 cache 当 0；优先保存上游费用及来源，另算估价时标明缺失维度和假设。
4. **更新包与构建来源。** [runtime-manifest](/Users/kgm/Projects/merico/deep-swe/wip/config/runtime-manifest.json:1)、[统一 runtime package](/Users/kgm/Projects/merico/deep-swe/wip/agents/deep_swe_agent/runtime/package.json:12)及 lockfile 同步，再重建 runtime 镜像、digest 和执行计划。任务容器只挂载预构建 runtime，修改 package.json 本身不会更新已存在镜像；见[Docker 构建](/Users/kgm/Projects/merico/deep-swe/wip/docker/agent-runtime/Dockerfile:62)与[挂载校验](/Users/kgm/Projects/merico/deep-swe/wip/agents/deep_swe_agent/pier_agent.py:264)。同步核对 Docker ARG 默认值。
5. 旧 `deep_swe_collab` 入口仍固定 0.20.0，且有独立 runner/Pier 统计消费；若继续支持，必须同步 package/lockfile、Python 默认版本和用量迁移，不能只升级统一入口。[旧入口默认值](/Users/kgm/Projects/merico/deep-swe/wip/agents/deep_swe_collab/pier_agent.py:91)、[旧 runner](/Users/kgm/Projects/merico/deep-swe/wip/agents/deep_swe_collab/runtime/src/agent-runner.ts:164)。

OpenCode 0.23 起拒绝显式 `maxTurns`（含 0），但两个现有 runner 均未传入，当前不构成阻断。我们的 stage timeout/总 deadline 继续有效。Modifier 顺序续跑、Reviewer fresh 的现有模式也无需改成 tmux-play。当前 CligentRunner 缓存同一个 Cligent/adapter 实例，适合 Codex 的本轮差值基线；若以后从持久化 token 恢复并重建 adapter，首轮可能没有可信用量基线，应接受 tokens 缺失。

## 迁移验收建议

- 新旧 usage 事件夹具覆盖 reported zero、无 tokens、partial、缓存/reasoning 不重复加、费用来源、多模型、混合完整性；穿过 runner → summary → Pier/ATIF → token_usage，防止只修一层。
- 使用正式 package/lockfile 做干净安装和 runtime 镜像构建，运行 manifest 一致性检查及受影响测试。
- Claude fresh/resume 验证每轮单 init，含子 agent 的任务检查 records；Codex 两轮续跑检查差值及 partial。
- OpenCode 使用匹配的 SDK/CLI，检查工具参数/结果、auto 权限、文本/delta、终止和两轮续跑归属；保留 watchdog 清理回归。
- Kimi 验证成功终止且 tokens/cost 仍未知；若接入 SESSION_RESUME_REJECTED 恢复，再测试仅前置明确拒绝可走恢复路径，普通执行错误不自动重试。

以上完成后再切换正式评测基线；目前的结论是“适合做一次带统计协议迁移的升级”，不是“已完成线上升级验证”。
