## 结论

有明确升级收益，但不是只改版本号即可：0.21.0 修改 usage 公共结构，0.23.0 拒绝 OpenCode 显式 `maxTurns`。其他新增能力多数可按需接入。以下是上游层结论，项目调用点和包安装验证由主评估补齐。

## 运行时与非核心新增

Node 要求仍 `>=18.3.0`，三个可选 peer SDK floors 未变：Claude `>=0.3.219`、Codex `>=0.144.0`、OpenCode `>=1.18.12`。实际 tested/repair pins 更新为 Claude SDK `0.3.251`、Codex SDK `0.151.0`、Gemini CLI `0.57.0`、Kimi `0.39.1`、OpenCode SDK/CLI `1.18.25`；Gemini floor 放宽到 `0.45.1`。包依赖 ACP SDK 从 `1.3.0` 到 `1.4.0`。来源：[package.json](/Users/kgm/Projects/merico/cligent/package.json:82)、[targets](/Users/kgm/Projects/merico/cligent/src/runtime-targets.ts:98)。

0.24 新增 Claude/Codex `fastMode` 可选请求及观察；其他三家连显式 `false` 也不能随意传，省略保留 provider default。0.21–0.23 大量 tmux-play managed lifecycle / call settings 工作对直接消费 Cligent/adapters 的调用方通常没有直接迁移需求；只有实际使用 tmux-play 才需检查 tmux >=3.3 等变更。来源：[0.24 发布记录](/Users/kgm/Projects/merico/cligent/CHANGELOG.md:26)、[0.21–0.23 发布记录](/Users/kgm/Projects/merico/cligent/CHANGELOG.md:40)。

## 对补丁调整的边界

上游重复 init 已修复；本项目未发现专用 Claude init 补丁，不能列为待删项，actualModel 首值保护可保留。若其他调用方有专用补丁，可在迁移测试后撤掉。usage 适配必须整体迁移并保留 unknown/partial/source，而不能继续使用旧 tokenAvailability 的上游读取逻辑。OpenCode 显式 maxTurns 必须调整。现有超时监控、残留交互请求 fail-fast、业务重试权限与进程组清理并未被新版本取代。历史 0.18 补丁是否仍存在需按当前代码判断，不能从旧评估文档推断还需要再删一次。
