# cligent 0.20.0 升级评估

日期：2026-08-13  
评估范围：`@sublang/cligent` `0.18.0` → `0.20.0`；dogfooding `CLI-001`～`CLI-007`；deep-swe unified runtime 现有兼容补丁。  
证据边界：评估阶段只使用 cligent 本地仓库 `v0.20.0`（commit `b35a468`）的源码、spec、测试、changelog，deep-swe 本地源码/问题记录，以及 npm registry 的包元数据；随后按下述实施状态修改 deep-swe。

## 实施状态（2026-08-13）

本报告提出的升级迁移已在 deep-swe 工作树实施：两套可执行 runtime 均固定到 npm
`@sublang/cligent@0.20.0`，0.18.0 专用 postinstall patch 与旧 compat test 已移除；统一
runtime 已恢复 OpenCode `text_delta` 的落盘和 finalText 合并，删除 prompt 内容匹配，并将
`tokenAvailability` 传播到 role summary、Pier context、ATIF 和下游 token/cost 报告。外层 event-silence watchdog、
残留 permission fail-fast、总 deadline 和进程树清理继续保留。真实 provider smoke 仍按用户
安排留待人工执行，因此 dogfooding issue 当前标记 `Released`，尚未标记 `Verified`。

离线验收已通过：两个 TypeScript runtime 共 110 项测试，`wip` 完整 Python suite 169 项
测试（其中 Pier/ATIF/统计脚本 53 项、agent-eval 89 项）；两个安装目录的 `npm ls` 均解析为
`@sublang/cligent@0.20.0`。

## 结论

**建议升级，但不能把 `0.20.0` 当作只改版本号的 drop-in upgrade。** 上游 0.20.0 从代码和回归契约上已经覆盖 `CLI-003`～`CLI-007`；`CLI-001`、`CLI-002` 是 0.18.0 已发布的修复，0.20.0 仍保留对应实现和回归测试。依赖基线也兼容 deep-swe 当前 runtime：cligent 要求 Node `>=18.3.0`、Codex SDK `>=0.144.0`、OpenCode SDK `>=1.18.12`，deep-swe 当前分别为 Node 22、`0.146.0`、`1.18.13`（`cligent/package.json:76-77,93-107`；`deep-swe/wip/config/runtime-manifest.json:4-15`）。npm 元数据于 2026-08-13 核验版本确为 `0.20.0`，integrity 为 `sha512-xmQL...Pjwbn9A==`。

实施时同步完成了三个必须迁移项：

1. **删除 0.18.0 专用 postinstall patch，否则安装会硬失败。** `package.json` 每次安装都运行补丁脚本，而脚本明确只接受 `0.18.0`，发现 0.20.0 就抛错（`deep-swe/wip/agents/deep_swe_agent/runtime/package.json:6-9,16`；`deep-swe/wip/agents/deep_swe_agent/runtime/scripts/apply-cligent-compat-patches.mjs:14-22`）。所以只更新依赖与 lockfile 会使 `npm ci` 失败。
2. **消费并传播 `usage.tokenAvailability`。** 0.20.0 将它设为必填判别字段；`unavailable` 时两个 token 数字只是兼容占位符，不能当作实测 0（`cligent/src/types.ts:85-98`；`cligent/CHANGELOG.md:13-18`）。deep-swe 当前在 runner、汇总、Pier context 和 ATIF 中都丢弃该字段并直接累加数字（`deep-swe/wip/agents/deep_swe_agent/runtime/src/agent-runner.ts:40-45,425-440`；`deep-swe/wip/agents/deep_swe_agent/runtime/src/direct-engine.ts:128-142`；`deep-swe/wip/agents/deep_swe_agent/pier_agent.py:588-608`；`deep-swe/wip/agents/deep_swe_agent/atif.py:123-138,182-188`）。如果不迁移，`CLI-003` 虽在上游修好，下游仍会把 Kimi unavailable 记为真实零值。
3. **OpenCode `text_delta` 必须恢复为正式输出，而不是继续丢弃。** 0.20.0 只把 assistant 文本 delta 映射为 `text_delta`，推理 delta 已抑制；若 delta 已完整重建 settled text，settled `text` 会被去重不再发出（`cligent/specs/user/adapters/opencode.md:93-126`；`cligent/src/adapters/opencode.ts:469-487,1874-1883`）。deep-swe 当前落盘时丢弃所有 OpenCode `text_delta`，内存 finalText 又只累积 `text`（`deep-swe/wip/agents/deep_swe_agent/runtime/src/agent-runner.ts:67-83,370-398,463-464`），升级后会丢失正常回答。应按事件顺序同时累积/保存 `text` 和 `text_delta`；ATIF 转换器本身已经支持两者（`deep-swe/wip/agents/deep_swe_agent/atif.py:87-94`）。

完成这三项和下文的定向验证后，结论是 **Go**；在此之前是 **No-Go（安装阻断 + 输出丢失 + usage 语义仍错误）**。

## 临时补丁/兜底处理清单

### 必须删除或修改

- 删除 `runtime/package.json` 的 `postinstall`；删除 `scripts/apply-cligent-compat-patches.mjs`。这是升级的硬阻断，不是可选清理（`deep-swe/wip/agents/deep_swe_agent/runtime/package.json:6-9`；补丁版本闸门见 `.../apply-cligent-compat-patches.mjs:14-22`）。
- 删除或改写 `cligent-compat.test.ts` 中“auto mapping 必须直接含 `external_directory: allow`”的断言。0.20.0 的安全契约刻意**不**追加 wildcard/枚举 allow，而是对 surviving ask 回复 `once`，保留显式 deny（`cligent/specs/user/adapters/opencode.md:142-158`）。旧测试会把新安全语义误判为回归。
- 从 `runtime-manifest.json` 移除 `compatibility_patches.cligent-0.18.0-opencode-auto-external-directory`，并把 cligent 版本改为 0.20.0（`deep-swe/wip/config/runtime-manifest.json:5-23`）。
- 删除 `isPromptEcho` 与 OpenCode 首条 text 重标逻辑及相应单测；它会违反 0.20.0 的“assistant 与 prompt 相同也必须保留”契约。
- 删除 `createEventFileSink` 对 OpenCode `text_delta` 的过滤；runner finalText 按原始顺序合并 `text` 与 `text_delta`。不要同时无条件追加 `done.result`，仍应避免重复。
- 为 `TurnUsage` 增加并传播 `tokenAvailability`；只有 `reported` 才累计/导出 token 总数。unavailable 情况保留 `toolUses`，token 汇总应为 unknown/null（或带 availability/provenance），而不是 0。

### 建议保留

- 保留 deep-swe 外层 event-silence watchdog、现场诊断和 process cleanup。上游 adapter watchdog 只覆盖 OpenCode SSE；外层 watchdog 覆盖 runner/其他 adapter 并保存 deep-swe 级诊断。默认情况下上游 300 秒会先终止，外层 600 秒只是后备。
- 保留 OpenCode residual `permission_request` 的 fail-fast，作为非 auto/异常路径的第二层保护；但更新注释和测试，auto 的正常审计事件现在是 `opencode:permission_decision`，不是 `permission_request`（`cligent/specs/user/adapters/opencode.md:176-208`）。
- 保留现有 `AbortSignal`、总 deadline/stage timeout 和进程组清理；这些是编排层责任，不与 cligent 的 adapter 内部清理重复。

## 其他兼容性变化

- **Breaking：OpenCode 显式出现 `allowedTools` 或 `disallowedTools`（包括空数组）即在加载 SDK 前拒绝。** deep-swe 当前 runner 没传这两个字段，所以不是当前阻断；以后不要为了“空配置”传 `[]`（`cligent/CHANGELOG.md:18`；`cligent/specs/user/adapters/opencode.md:367-374`）。
- `DonePayload.usage.tokenAvailability` 是 serialized event 的新增字段、TypeScript producer 的 required change。deep-swe 主要用宽松 `Record<string, unknown>` 读取，因此编译未必提醒；这反而要求显式补消费测试。
- 0.19.0 主要是 tmux-play/Captain 能力和 Claude resume repair，deep-swe 当前直接使用 `Cligent`/adapters，不构成已发现的 API 阻断（`cligent/CHANGELOG.md:32-42`）。
- npm 发布的 peer floors 与仓库 `package.json` 一致；当前 deep-swe 精确版本均满足。正式使用仍应从 npm 安装，不依赖本地 cligent checkout。

## 建议升级与验收顺序

1. 先删除 0.18.0 postinstall patch/manifest 项和旧 compat test，再更新两个 runtime package/lockfile 与 runtime manifest 到精确 `0.20.0`。
2. 同一变更内完成 `tokenAvailability` 端到端传播，以及 OpenCode `text_delta` 的落盘和 finalText 合并；移除 prompt-echo workaround。
3. 运行 TypeScript build/unit、Python ATIF/Pier tests 和 runtime image build，确认 `npm ci` 不再执行旧 patch。
4. 做最小真实 smoke：
   - OpenCode auto 在 `/tmp` 写文件：无交互 `permission_request`，有 `opencode:permission_decision`，自然结束；
   - OpenCode reasoning + final answer：prompt 不回放，reasoning 不进入 `text_delta`，`text + text_delta` 恰好重建一次输出；
   - 静默 session：优先在约 300 秒由 cligent 给出 diagnostic/done，而非 600 秒才由外层 abort；
   - Kimi 无 usage：summary/context/ATIF 明确为 unavailable/null，`toolUses` 仍准确；
   - Codex command + MCP、OpenCode tool lifecycle：调用/结果成对且 `toolUses` 为唯一调用数。
5. smoke 通过后把 dogfooding issue 状态：CLI-001/002 从 Released → Verified；CLI-003～007 从 Open → Verified。若只完成静态/单测核查，则先标 Released，不直接标 Verified。

## 核查限制

- 本地 cligent checkout 没有安装 dev dependencies，定向执行 Vitest 时返回 `vitest: command not found`；本次没有为了评估修改/安装该仓库依赖。因此“已解决”是依据 0.20.0 的发布源码、完成状态 spec 和随源码提交的回归测试得出的静态结论，不冒充 deep-swe 的真实运行验收。
- 本报告没有执行需要 provider 凭据的 live Agent run；上述 smoke 是升级落地时从 Released 到 Verified 的必要门槛。
